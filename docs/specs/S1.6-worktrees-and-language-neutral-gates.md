# S1.6 — parallel worktrees and language-neutral gates

## Intent and governing boundary

The user requests native support for agent worktree parallelism and non-JS projects (especially Python). Current project discovery only builds npm commands; project profiles require package.json and JS/TS evidence paths. Worktree snapshots are already content-addressed, but lifecycle mutations only have a Pi in-process queue and Spec ID allocation is not shared across checkouts.

This is a new capability contract, derived from S1.2/S1.4/S1.5, not a reopening or relabeling of their audit results. User explicitly authorized **at most three fresh-model reviews for S1.6** (proposal, implementation, one re-review). No push/release/deploy/GitHub settings or example-app mutations are authorized by this contract. Existing S1.5/example-app 63 remain in-progress; their review gaps are not closed by this work.

## Contract

### 1. Worktree-local truth, repository-family coordination

- Resolve real Git toplevel, per-worktree git directory and common git directory using Git argv, including linked `.git` files, paths with spaces and detached worktrees. Specs, gates, ledger and snapshots belong to the **current checkout**, never an arbitrary main checkout. No scoped/partial snapshot may masquerade as whole-project evidence; content-changing merges/rebases must rerun impl/audit.
- Add `worktrees` CLI showing checkout path, branch/HEAD, local specs and explicit live freshness of active impl records (no spec directories is an empty checkout, not an error). It is informational and cannot transplant evidence or silently alter another checkout. Current board and Pi commands stay compatible.
- Add a numeric / numeric-suffix Spec ID allocator (`spec-alloc [--prefix PREFIX]`) that scans all registered available worktrees and persistent local reservations, then reserves the next ID atomically under the Git **common directory**. The ID is PREFIX + the unpadded smallest positive integer strictly greater than every observed/reserved numeric suffix in that exact namespace (empty prefix = numeric IDs); prefix is a safe literal string, not a regex. Also inspect matching filename stems so an unmanaged candidate cannot be silently reused. No duplicate ID from concurrent cooperating callers; removed worktree reservations remain burned, not reused. This is allocation metadata, not another governing contract. Worktree missing/inaccessible/malformed inventory fails closed, rather than guessing a free ID. This allocator does not guard arbitrary hand-written IDs or separate clones/machines.
- Put cross-process exclusive locks for begin/impl/audit/attest/done in the common Git directory, keyed by canonical Spec ID. Different IDs/checkouts can proceed independently; the same ID reports a clear busy owner and asks for retry. Release on normal failure and cancellation. Never automatically steal an uncertain stale lock (SIGKILL recovery requires verifying no owner is active). Existing Pi mutation queues remain in place.
- Use optimistic spec-file content checks before lifecycle writeback: concurrent edits during gates/audit must not be overwritten. Pending impl invalidation remains before gates. Take implementation snapshots before and after the gates/E2E window, excluding only current spec/ledger as before; changed content records a nonpassing impl with a diagnostic. Gate-created caches/artifacts must be ignored or stable; generated tracked changes require a subsequent rerun. A passing impl must not certify code changed during the gate window. Locks do not control unrelated editors/Git operations and are not a security sandbox.
- Keep `impl.repo` compatibility for unconfigured historical users; configured profiles still require branch-local contracts/implementation. Use `cd WORKTREE` (not a main contract pointing to sibling paths) for parallel work. Preserve portability: no machine-specific worktree paths required in committed evidence. Add opt-in `check --ci --live` to check active implementation content now (also allowed with --contracts-only); mismatch is an error, pending impl has no snapshot to compare, done history is not compared to today's code. Ordinary CI keeps historical record-consistency semantics.

### 2. Explicit language-neutral execution, backward compatibility

- Extend strict `.spec-flow.json` v1: lifecycle is optional (defaults to existing review.decision/status/deps behavior); gates is optional (default detection) or `{"mode":"replace","npmScripts":["verify"]}` / `{"mode":"replace","commands":[{"name":"test","argv":["python3","-m","unittest","discover","-s","tests"]}]}`. Gates accepts **exactly one** non-empty npmScripts/commands list. Names match `[A-Za-z0-9][A-Za-z0-9:_-]*`, are unique and not prototype keys; argv is nonempty string-array, no NUL/newline; argv[0] is a bare PATH executable or lexically in-checkout relative executable path, never absolute/parent traversal/leading option. Local interpreter symlinks (normal Python venv behavior) are trusted executable code, not evidence files. Gates-only profiles retain default lifecycle and its proposal-approval enforcement. `commands` entries contain only `name` and `argv`; no implicit shell, env/cwd interpolation, dynamic plugins, unknown keys or executable path traversal. Execute via argv in the current checkout. Commands are trusted project code, not a sandbox. Existing npm profiles and default JS detection retain their semantics.
- Python projects may use `python3 -m pytest`, `.venv/bin/python -m pytest`, `uv run --no-sync ...`, or stdlib unittest through explicit profiles, without package.json. Detect an explicit pytest configuration (pytest.ini / pyproject tool.pytest.ini_options) conservatively; prefer checkout-local .venv interpreter when available, otherwise python3. Do not invent optional ruff/mypy gates, install dependencies or execute Python packaging code. A recognized Python project with no unambiguous gate requires configuration instead of a green empty gate set.
- No-gate implementation records pass:false, required_gates:[] and a clear diagnostic: empty required gates cannot create new green evidence. Ordinary no-profile/no-language external commit behavior stays compatible; explicit full CI/commit gating on a recognized Python project with missing gates fails; the Action's verify CLI also fails without any executable gate, including otherwise-unrecognized projects. contracts-only always discloses that **project gates** (not only npm) were skipped.
- Add optional strict `evidence` configuration: `{"e2e":{"dir":"tests/e2e","extension":".py","runner":["python3"]},"migrations":{"dir":"migrations","extensions":[".py",".sql"]}}`. e2e/migrations sections may be omitted individually; each present section requires all its documented fields and rejects unknown keys. dir is normalized in-checkout relative path without absolute/parent traversal or leading options; directories must resolve within the checkout; extension(s) match `.[A-Za-z0-9]+`, migration extensions unique/nonempty. Runner uses the same argv validation as commands and appends the verified E2E filename as its final argument. `migrate-alloc` honors configured migration paths/extensions. Defaults remain tests/e2e/e2e-*.mjs via Node and numeric TS migrations; `.py` E2E and `.py`/`.sql` migrations are supported when configured. Maintain basename, regular-file, no-symlink/path-escape checks and E2E exit-0 + PASS/FAIL protocol. No DB/framework-specific migration execution is inferred.
- Composite Action invokes a `verify` CLI that runs full configured gates when configured, preserves the old no-config `package.json#scripts.verify` entrypoint exactly once when present, otherwise runs detected gates (including Python) via the same `checkCI` validation. It no longer hard-codes `npm run verify` for every caller. It still installs its own locked Node runtime deps, supplies SPECFLOW_CLI for nested contracts-only checks, and never installs caller language deps or requires a PAT. Caller provisions Python/Node/etc and pins a published commit themselves. Preserve example-app's existing profile: verify runs exactly once, no recursion.
