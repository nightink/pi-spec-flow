## In scope

1. **Shared engine and sealed jobs.** One packet builder/executor/protocol under spec-flow, reused by read-only `spec_review` and lifecycle `spec_audit`. A packet is built once; SHA-256 covers the exact bytes checked by the engine's named high-risk-pattern scanner and passed to the isolated child. Preserve packet, raw response, structured receipt and execution state in private Git-common-dir coordination storage. Reject oversize/malformed input, secret match and tampered packets before model execution; validate result after execution and retain malformed raw responses as nonpassing. Persist a caller-authorized finite budget; nested entry points share it and reserve once before potentially metered execution. Do not auto-grant or reset budget on restart. Local coordination is neither an anti-tamper ledger nor another contract.
2. **Exact review boundaries.** Native tool and CLI support explicit base/head (resolved full SHA-1/SHA-256 commit IDs), verified ancestry and two-endpoint diff including metadata/stat/name-status/check. Read the governing contract from the specified head for committed review, not the dirty filesystem. Default reject dirty checkout unless explicit committed-only exclusion accepted. Preserve whole original implementation base; incremental review has a separate review base and previous structured report. Blocking incremental findings must be introduced-by-diff, regression or incomplete-fix, with changed-hunk evidence. Unchanged baseline issues cannot alter the incremental verdict. Empty diff is a non-model `skipped` result, never an independent audit PASS. Proposal mode may reuse isolation machinery, but does not use empty-diff approval. Existing working-tree audit covers committed/staged/unstaged/untracked material, bound to verified impl/contract; read-only historical/delta approval cannot automatically close today's Spec.
3. **Structured output and Pi registration.** `spec_review`, `spec_new`, `/spec review`, `/spec new` and CLI equivalents. Machine-usable results plus model-facing text; Pi 1.x outputSchema/structuredContent support where appropriate. Keep APIs usable without UI. No model call merely on discovery/load/dry-run. Distinguish raw independent verdict from parent dispositions, scope coverage and runtime evidence. Retain compatibility with old valid criteria/scope-deviations audit shape; do not rewrite completed Spec evidence.
4. **Pi project recognition.** Statically inspect declared `package.json#pi.extensions` and conventional project extension locations, entry presence and paths without importing/executing targets. Include bounded, hash-bound recognition data in review packets. Recognized declaration is not proof of load or behavioral compatibility. Actual extension/tool/command discovery is verified separately with a trusted isolated real Pi fixture and no model call; never automatically run an unknown target extension.
5. **Deterministic creation.** `spec_new` takes schema-validated structured fields, atomically reserves a shared-family ID and exclusively creates one canonical file. Never overwrites, adopts an existing Spec or reuses a burned reservation. Built-in versioned template fixes frontmatter and sections (outcome, scope/non-goals, design, ordered plan, executable acceptance, evidence/review). New Spec uses a new default pre-review draft + review.decision=pending while preserving legacy pending/startable behavior; an explicitly configured lifecycle must have a preReview status or creation fails before reservation/write. No automatic approved/active/done state, no impl/audit/attestations; project governance must later move a draft to a startable approved state. YAML-safe titles, mapped lifecycle/dependency fields and numeric-project filenames; fixed placeholder content can create an honest incomplete draft. An optional strict profile creation policy may specify a recognized directory, a safe body-only template and allowed metadata defaults for project-required fields. No JS/template evaluation, symlink/outside-root templates or arbitrary caller-supplied frontmatter. Templates are authority-aware; unsupported required metadata fails instead of being invented. Scaffolding controls generation, not a sandbox against later authorized edits.
6. **Retire duplicate entry.** Update autonomous-delivery instructions to route Spec creation and implementation review to spec-flow without double calls/new authority. Archive the existing global independent-spec-diff-review directory outside skill discovery (reversible, no historical-report deletion) only after replacement passes actual discovery. Keep a tracked copy/change manifest for the global skill changes and record installed paths. No silent project-override/collision bypass.

### Creation policy v1

Optional `.spec-flow.json.creation` exact keys: `directory` (one of the four scanned Spec-directory candidates), `template` (normalized relative regular body-only Markdown path), `defaults` (plain JSON scalar/array defaults for safe project-required metadata; reject prototype keys and reserved id/title/status/review/workflow/impl/audit/attestation/evidence/scope/dependency/update fields). No configured directory: use the only existing recognized directory; zero => create `docs/specs`; several => fail and require policy. A configured directory may be created only under a validated non-symlink checkout parent.

Template identity is `{version: 1, sha256}`. Body must start with a heading, not YAML frontmatter, <=64 KiB, and use known literal slots `{{title}}`, `{{goals}}`, `{{non_goals}}`, `{{design}}`, `{{plan}}`, `{{acceptance}}`; all required content slots occur exactly once, no unknown/unresolved expressions. Built-in template is tracked and versioned. No evaluation. Structured caller input exact keys: title, prefix?, slug?, goals?, nonGoals?, design?, plan?, acceptance?, dependencies?, dryRun?. Text items are bounded single-line strings to prevent section injection. Missing semantic fields yield explicit TODOs in a nonapproved draft. Slug is safe ASCII `[a-z0-9][a-z0-9-]*` (bounded; no path/control/addendum when prohibited), default `spec`; filename `<id>-<slug>.md` for prefixed IDs and `<number>.<slug>.md` otherwise. Numeric validation requires no prefix and YAML integer id. Default kind is `spec`; if project kindField/allowedKinds differs require a valid configured default, never guess. Unknown unfillable required metadata fails before ID reservation. Mapped dates/dependencies/status-line policy applied; ordinary output `{id,path,status,template}` plus a ledger creation event, never stage/commit. Reservation and exclusive file publication happen inside the family allocator lock; on later file-publication failure the reservation stays burned. New Specs alter other active whole-repo snapshots; create before impl or revalidate affected active work.

### Review modes and result

| mode | input / contract source | scope / effect |
|---|---|---|
| proposal | current declared Spec file, exact file hash | no diff shortcut; proposal evidence only |
| committed | base/head resolved commits; Spec and profile blobs from head | exact two-endpoint range; dirty tracked/staged/untracked rejected unless allowDirty explicitly records exclusions |
| incremental | same endpoints + prior engine job/report ID and hash | separate review base, prior closure matrix, blocking finding class/path/changed-line checked; baseline observations do not block |
| working-tree-audit | internal lifecycle adapter, begin base plus verified current impl/contract/snapshot | full committed/staged/unstaged/untracked patch; only spec_audit may write fm.audit |

`spec_review` has `action: prepare | run | status`; prepare/empty-diff/status are nonmetered. CLI `review --json <object>` mirrors it; `/spec review <JSON>` is handled without asking the host model. `spec-new --json <object>` and `/spec new <JSON>` mirror spec_new. Both native tools return model-facing JSON and structuredContent/outputSchema for Pi 1.x programmatic callers. Read-only reviews never change status, review.decision, impl, audit or attestations, even after proposal/delta PASS.

A versioned receipt records job ID, mode, contract/blob/profile/packet hashes, endpoint/snapshot identities, scan name/result/hash, execution state, requested/effective model, thinking, usage if observed, budget/call reference, raw-result hash and normalized result. Result retains legacy criteria/scope_deviations plus structured findings (`id`, `classification`, `file`, `line`, evidence), prior closure and out-of-scope observations. In incremental mode out-of-scope cannot fail criteria/verdict; malformed or unclassified blocking findings fail validation. Preserve the model's raw response unchanged; parent dispositions are separate. Working-tree empty diff stays a fail/unverifiable audit (optionally marked skipped), never PASS; ordinary empty diff is skipped with model_invoked=false. Existing v2 stored audit shape remains additive and completed contracts are untouched.

### Budget, storage and packet identity

Finite budgets keyed by explicit **delivery-cycle ID** within the Git common directory; neither Spec ID nor a new tool invocation silently creates a grant. Public terminal/API authorization records a user-approved note and finite maximum (may seed already-used external proposal calls); existing grants are immutable. Model-facing tools can consume a named grant but cannot create/increase/reset one. Caller/orchestrator owns consent; local writable metadata is not a tamper-proof authorization system. Cache reuse happens before budget lookup and costs zero. After input/hash/scan preflight, job claim + charged reservation under shared locks occurs once before spawn; failure/cancellation/interruption is conservatively charged without refund. Same job never silently respawns; a new user-approved cycle is separate authorization. Mechanical fake-auditor tests create synthetic explicit grants in disposable repos, never consume this delivery's real budget. Harness proposal call 1 is seeded when authorizing the engine budget, so the combined real cycle remains <=3.

Own versioned storage `.git-common/spec-flow/review-v1/{budgets,jobs}` (0700 directories, 0600 files, atomic JSON state); never inspect/modify legacy `spec-flow/jobs/*` such as S1.6-recovery. Packet == **entire exact child prompt bytes**, passed via @file, not a separately reconstructed embedded payload. Hash is sealed before the named builtin high-risk-pattern scanner, rechecked immediately before execution and recorded as both packet_sha256 and child_input_sha256. Full packet <=512 KiB (existing bounded audit limit retained); raw output <=32 MiB; overflow stops execution, preserves bounded captured bytes with truncation state, never passing. No overrides that silently truncate a review diff. Head profile/contract blobs each bounded; endpoint Git commands use argv, --end-of-options, --no-ext-diff and --no-textconv. diff --check failures are disclosed as data. Foreign/unknown job dirs ignored. Preserve state/results before frontend delivery; no automatic restart/retry. Completed prepared working-audit job may be attached to audit without another model call only after current scope/snapshot/contract/spec identity and exact diff/impl-payload checks; arbitrary committed/delta jobs cannot be attached. The lifecycle packet carries the whole current Spec separately; exclude that Spec's duplicate diff (including lifecycle writeback) and the reserved lifecycle ledger to keep preparation/resume stable. Use deterministic new-file headers, retain original review HEAD provenance, and recheck the snapshot before spending and after review; a same-content commit is not a new implementation.

Isolated child flags: print/JSON, no-session, no-tools, no-extensions, no-skills, no-prompt-templates, no-context-files, no-themes, no-approve; preserve @file and existing SPECFLOW_AUDIT_* model/thinking/timeout/bin compatibility. Real host tests use explicit trusted extension paths and private agent state, offline, no model. A trusted fixture command invokes the registered tools through ctx.executeTool; verify structured return and absence of model-run events. No arbitrary target execution.
