# S1.5 — project contract validation and shared private Action

## Intent / governing boundary

example-app's Spec 0 remains the authority for its document conventions, while this project supplies the reusable parser, state/evidence workflow and deterministic validator. The user chose a private cross-repository GitHub Action instead of vendoring the engine; there is **no publish or push authorization**. example-app's replacement of `scripts/spec-meta.mjs` must not silently lose required fields, numeric filename ↔ ID, kind/status, checked `done`, dependency existence/cycles or forbidden addendum checks. Other projects without an opted-in profile must retain S1.4 behavior.

The Action is only a reproducible CI entry point; global `autonomous-delivery` orchestrates the same governing project Spec, not another ledger. example-app's local `npm run verify` must still be authoritative, but must not recursively run itself when its spec metadata check calls spec-flow. The Action must run a pinned SHA, run without PAT, and fail closed if its code or dependencies are unavailable. Human GitHub access settings and a real remote run are out of scope of local tests; do not claim them complete.

## Contract

1. Strict `.spec-flow.json` v1 gains optional `validation` with explicitly allowed keys only: `requiredFields` (safe unique frontmatter names), `kindField`, `allowedKinds`, `numericFileId`, `checkDoneCheckboxes`, `forbidAddendumFilename`, `dependencyIntegrity`. Reject unknown keys, invalid types, colliding keys and path/shell execution. Omitted `validation` changes no existing behavior. Apply configured checks to *every* discovered spec, including ignored/legacy, before legacy compatibility `continue`.
2. `numericFileId` requires a safe integer `id` matching a basename of the form `N.*.md` (no subdirectories/other ID formats); forbid duplicates (already enforced). `checkDoneCheckboxes` uses root-level `- [ ]` for `done`. `dependencyIntegrity` requires array of safe nonnegative integer IDs, existing targets, and detects cycles of arbitrary length; a configured profile may still allow legacy active IDs individually but cannot bypass these document rules.
3. `check --ci --contracts-only` performs the same document/evidence/profile validations as ordinary `check --ci` but intentionally skips npm gates and labels that omission in output. Bare `check --ci` continues to run all configured gates without caching; malformed/unknown CLI flags fail closed. An `impl` gate that runs `npm run verify` may call contracts-only without infinite recursion.
4. Add a composite GitHub Action at `action.yml`: install spec-flow's locked runtime dependencies from its own checkout; check the caller's specs and run the caller's `npm run verify`, handing it the verified Action-local CLI path. No arbitrary shell/configured executable from Action inputs, no PAT, no release/deploy, least privilege caller permissions. Caller must pin a full commit SHA, not a mutable branch/tag.
5. Add tests for positive/no-profile and negative schema/metadata/3-node cycle/legacy bypass/done checkbox/CLI recursion cases; test action shape and actual local Action-equivalent command chain. Document remote same-account private Action Access setup, two-repository ordering, and the non-claim of remote acceptance before the user's settings/push.

3. Implement and static-check `action.yml`, exercise its child commands with a disposable example-app-shaped fixture and installed local dependencies; document SHA pin/permissions and unpushed limitation.
