# 项目级 spec 目录发现

- 状态：已完成

## 目标

让 spec-flow 同时发现以下四个显式目录中的 Markdown spec：

- `docs/spec/`
- `docs/specs/`
- `spec/`
- `specs/`

现有 `docs/specs/` 行为必须保持兼容。

## 验收标准

- 四个目录均可独立被扫描，目录不存在时不报错。
- 多个目录同时存在时，所有目录中的直接 `.md` 文件都会被合并，顺序稳定且不递归扫描其他目录。
- 目录内的无 frontmatter 文件继续作为未纳管 spec 展示；带 frontmatter 的文件继续参与生命周期、依赖和 CI 检查。
- 重复 spec ID 不被静默选择：`check --ci` 报错，按 ID 执行生命周期操作时拒绝歧义目标。
- 项目目录为符号链接时，只接受 realpath 仍位于项目根内的候选目录，不读取项目外部文件。
- board、Pi `/spec` 命令、README 和空目录提示不再只声称 `docs/specs/`。
- 真实 CLI E2E 覆盖根目录单复数与 `docs/` 单复数目录发现。

## 非目标

- 不递归发现任意名称或任意深度的 spec 目录。
- 不引入 `specflow.json` 配置文件。
