# S1.2 可信门禁与终态证据闭环

- 状态：已完成
- 规模：L
- 依赖：S1.1

## 背景与已观察事实

当前实现已经具备 `begin → impl → audit → attest → done` 主流程、commit 门禁、独立审计与 JSONL 台账，但 2026-09-17 的仓库评估确认了以下可复现缺口：

1. `treeHash()` 使用未导入的 `execSync`，异常被吞为 `null`；缓存条件又把 `null` 当成任意命中，造成 5 分钟内假红/假绿。
2. 声明的 e2e 在目录为空时被跳过，`spec_impl` 仍可 PASS。
3. 迁移冲突可让 `spec_impl` FAIL，但冲突未持久化，随后 `spec_done` 仍可成功。
4. `audit.verdict=pass` 与 `criteria[].status=fail` 可以并存，`spec_done` 只看 verdict。
5. 审计 diff 把 frontmatter 的 `base_sha` / `scope` 拼入 `shell: true` 命令；审计子 Pi 未禁用工具与 session。
6. Pi 默认并行执行 sibling tool calls，但写 spec 的工具未接入 `withFileMutationQueue()`；工具 catch 返回的 `isError: true` 按 Pi API 不生效。
7. `spec_attest` 可由模型直接写入“人工核验”，没有用户确认。
8. 本仓库没有自举的 npm test/check 门禁；`check --ci` 在零门禁时仍返回成功。

本 spec 将这些问题作为同一条“证据必须完整、可绑定、不可因空值或并发而假通过”的纵向修复处理。

## 用户可观察结果

- gate 缓存默认关闭；显式设置非零 TTL 后，只有同一工作树指纹、门禁定义与运行时摘要才允许复用，指纹不可用时必定重跑。
- 所有已声明 evidence 都必须产生明确结果；缺失、非法路径、未执行和迁移冲突均不能被空集合吞掉。
- `spec_done` 只接受显式通过、内部一致、与当前实现快照及当前 spec 合同一致的 impl/audit/attestation。
- 审计不再通过 shell 拼接 Git 参数；大 diff、Git 失败或非法审计 JSON 均 fail closed。
- 审计子进程没有文件/命令工具，不保存 session；仓库中的 prompt injection 不能借审计进程执行工具。
- Pi 内并发调用不会静默覆盖同一 spec；工具失败在 Pi 事件中表现为真实错误。
- 从 Pi 调用人工核验时必须由用户在 UI 中确认；无 UI 时拒绝，并提示使用显式 CLI。
- 本仓库可通过一个权威 npm 命令运行语法检查、单测、spec CI 与 e2e。

## 非目标

- 不把扩展宣称为安全沙箱，也不阻止拥有文件写权限的用户故意篡改 YAML/ledger。
- 不实现跨进程分布式锁或不可篡改签名账本；本轮只保证单个 Pi 进程内与内置 edit/write 的文件队列一致性。spec/cache 使用同目录临时文件 + rename，JSONL ledger 保持 append-only。
- 不实现完整 shell AST；复杂/多 commit 命令的保守处理列为后续项。
- 不改变 `SPECFLOW_BYPASS=1` 的显式兜底语义。
- 不发布 npm 包、不 push、不部署。

## 不变量与安全边界

1. **缓存不变量**：默认 TTL=0、不读写结果缓存。仅显式 opt-in 时，`fingerprint != null`、缓存/指纹版本一致、门禁定义与 Node 主版本摘要一致且 TTL 有效才可命中；指纹失败必定执行门禁并暴露原因。缓存只是性能选项，不是证据来源。
2. **证据完整性**：`impl.pass` 必须显式为 true；每个 `evidence.e2e` 都有结果；迁移冲突持久化；空对象不能代表“已验证”。
3. **快照绑定**：workflow v2 的实现快照在实现仓库（`impl.repo || cwd`）计算，覆盖 Git tracked + untracked 当前文件内容、可执行位、删除标记与 submodule HEAD；排除 ledger，以及当前 spec 文件（仅当它位于实现仓库内）。impl、audit、attestation、done 绑定同一 hash。live snapshot 只在 audit/done 转换时重算；CI 不用今天的源码否定历史 done spec。
4. **合同绑定**：contract hash 包含规范化 frontmatter 合同字段和正文。排除 `status/workflow_version/impl/audit/attestations`，`review` 只保留 decision；正文移除状态行、把 `[x]/[X]` 归一为 `[ ]`、排除“Review 与决策”章节内容。修改目标、设计、验收文字、依赖、scope 或 evidence 会让旧证据失效；勾选 checklist 和写回审查证据不会形成循环。
5. **审计一致性**：pass 必须至少有一个 criterion，且所有 criterion 均为 pass；非法/缺失字段统一降级为 fail/unverifiable。
6. **命令边界**：Git diff 使用 argv；scope 只作为 pathspec；e2e id 只能是 `tests/e2e/` 下的 `e2e-*.mjs` basename。
7. **Pi 并发语义**：对同一 spec 的完整读改写窗口进入 `withFileMutationQueue()`；错误通过 throw 交给 Pi。
8. **人工语义**：Pi 工具只能在 `ctx.hasUI` 且用户明确确认后登记；确认展示 item+note 并透传 signal。CLI 调用视为用户显式操作。
9. **验证分层**：record-consistency 检查存量字段、hash 互等、criteria 与 attestation，只供 done/checkCI；live-freshness 额外重算当前实现 snapshot，只在 audit/done 使用。
10. **兼容性**：legacy done spec 只读并 warning；legacy in-progress 的 impl/audit/attest/done 拒绝并要求显式重跑 `spec_begin` 迁移。

## 设计

### A. 门禁指纹与缓存

- 将同步 `treeHash` 改为可取消的异步 Git 指纹：HEAD、tracked diff、status、受大小上限保护的 untracked 内容摘要、规范化门禁定义与 Node 主版本共同参与 hash。
- `SPECFLOW_GATE_CACHE_TTL_MS` 默认 `0`；只有显式非零值才启用。缓存位于 `os.tmpdir()/specflow-<uid>/`（目录 0700、文件 0600），含版本字段，读取拒绝 symlink，写入使用同目录临时文件 + rename；`null` 指纹不读写缓存。
- opt-in 缓存明确不承诺感知 ignored 文件、外部服务和任意环境变化；需要强证据时保持默认关闭。指纹错误进入结果诊断，不再静默。
- 探测到的 npm/npx 门禁优先用 argv 执行，并禁止 npx 隐式下载。

### B. workflow v2 证据

- `spec_begin` 以 `impl.repo || cwd` 为实现仓库，设置 workflow v2，清除旧 impl/audit/attestations，并拒绝未知 Git HEAD。spec 文件使用原子 replace。
- `spec_impl` 总是逐项处理 declared e2e，校验 basename，持久化 `pass`、实现 snapshot hash、migration 结果与执行时间；snapshot 在 gates/e2e 完成后、写 spec 前计算。
- snapshot 使用受总字节上限保护的流式读取；tracked 删除记显式 tombstone，submodule 记 HEAD。超限、路径越界或 Git 枚举失败均 fail closed。
- 审计前要求 base 是当前 HEAD 的祖先。审计 patch = `git diff --binary <base> -- <scope...>`（覆盖从 base 到当前 working tree 的 committed/staged/unstaged tracked 内容）+ `git ls-files --others --exclude-standard` 枚举后的逐文件 `git diff --no-index`。`--no-index` 的差异退出码 1 单独视为成功；任一其他 Git 失败或总 patch 超过 `SPECFLOW_AUDIT_MAX_BYTES`（默认 512 KiB）时直接记录 fail/unverifiable，不截断、不使用占位 diff。
- `spec_audit` 先校验 impl 已 pass 且 live snapshot 未变，再记录 impl hash、contract hash、criteria、scope deviations、模型与 prompt 版本。缓存复用必须同时匹配 impl hash 与 contract hash。
- `spec_attest` 记录 impl hash 与 contract hash；done 逐项验证 attestation 的两个 hash。
- `spec_done` 先跑 record-consistency，再跑 live-freshness；workflow v2 任一缺口都拒绝完成。
- `check --ci` 对 workflow v2 done spec只跑 record-consistency 和当前 contract hash，不重算历史实现 snapshot；legacy done spec只 warning。

#### Legacy 状态矩阵

| 输入状态 | `spec_begin` | impl/audit/attest/done | `check --ci` |
|---|---|---|---|
| legacy pending/approved | review/deps 通过后迁移为 v2并清旧证据 | begin 前拒绝 | 校验基本 schema |
| legacy in-progress | 允许显式迁移，清旧证据并重记 base | 拒绝，提示重跑 begin | error，提示迁移 |
| legacy done | 拒绝重开 | 拒绝 | 只读 + migration warning |
| v2 pending/approved | 正常 begin，并覆盖/确认版本 | begin 前拒绝 | 校验基本 schema |
| v2 in-progress | 拒绝重复 begin | 严格 v2 | 严格检查当前记录 |
| v2 done | 拒绝重开 | 拒绝 | record-consistency + contract hash |

`workflow_version` 由 `spec_begin` 写入；proposal 阶段的 spec 不预置该字段。

### C. Pi 适配层

- 使用 `withFileMutationQueue` 包住 begin/impl/audit/attest/done 的完整调用；先通过 `findSpec()` 解析真实绝对路径，队列覆盖整个读改写窗口。
- 删除返回值中的伪 `isError`；异常直接 throw。
- 将人工确认门控抽成可注入 UI 的无宿主 helper 以便单测；`spec_attest` 展示 item+note，透传 signal，非 UI 模式拒绝。
- 对工具输出应用合理的长度上限；用无模型 RPC 启动做真实扩展加载与 `/spec` 命令发现冒烟。

### D. 自举与文档

- 固定 scripts：`typecheck = node --check core.mjs && node --check index.ts`；`test = node --test core.test.mjs`；`check = npm run typecheck && npm test && 两个 e2e && node core.mjs check --ci`。本仓库因此不再是零门禁；其他零门禁仓库仍保持 warning + success 的兼容行为。
- package 声明 Node `>=22.19.0`、标准 Pi `pi.extensions` manifest、pi-package keyword 与宿主 peer dependencies。
- 修正文档中的 `specflow.json`、audit 字段、人工核验、opt-in 缓存与平台边界描述；关闭 cache issue 时写明 ignored/环境变化只由默认禁用缓存保证，而非被 fingerprint 完全观测。
- 新增针对真实 CLI/子进程边界的 `e2e-trustworthy-closure.mjs`。

## Review 与决策

### 独立 proposal review（2026-09-17）

- 结论：`REQUEST_CHANGES`；3 Blocking，6 Non-blocking。
- B1 snapshot/contract 生命周期循环：**确认并修订**。明确实现仓、文件级 snapshot 排除、contract 规范化；拆分 record-consistency 与 live-freshness。
- B2 未提交/未跟踪 diff 与静默截断：**确认并修订**。base 必须为祖先；tracked working diff + untracked no-index；Git 错误/超预算直接 unverifiable。
- B3 legacy 矩阵缺失：**确认并修订**。新增完整状态矩阵，workflow_version 只由 begin 写入。
