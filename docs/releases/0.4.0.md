# 0.4.0 本地发布候选

**仅本地候选，未 publish / push / 远端打 tag；不是独立审查 PASS。** core 是唯一 npm 目标；root 和 Pi adapter 保持 private，adapter 经 Git 分发。S2.2、S21 仍未 done，真实审查预算 3/3 已耗尽；若发布政策要求独立 PASS，必须先取得额外授权并完成有效审查，不能把以下测试当成替代。

## 变化

- 显式 `audit --budget EXISTING_GRANT`，非法参数在创建 job/计次/写 Spec 前拒绝。
- 显式 repair/change 检查与 Action `purpose: strict|change`；默认 strict/done、审批、证据完整性及真实项目 gate 不降级。
- 合同内 context policy、准确来源/大小/UTF-8 字节偏移；旧 job 沿用封存策略。
- raw/typed 计数、未验证候选观察、真实停止遥测和启动期 core 版本/源码指纹。
- 私有逐文件 snapshot 漂移定位；不排除 tracked 构建产物，不改 aggregate 判定语义。
- `capture` 记录真实子进程的观察，区分正常失败与信号/超时/截断/漂移；不认证历史 red-first。

完整入口及风险边界见 [恢复指南](../recovery.md)、[逐项验收](../reviews/S21/validation.md)、[原反馈处置](../issues/2026-10-23-delivery-friction-from-kite-spec89.md#s21-父级处置补记原报告原文保留未核验的现场结论不升级成事实)。

## 留给发布者的远端步骤（此处未执行）

1. 确认本地已提交、工作树 clean，审阅上述独立审查欠账；在批准发布政策下固定 `RELEASE_SHA=$(git rev-parse HEAD)`。重新只读查询 `npm view @nightink/spec-flow-core@0.4.0 version`，仅确认不存在时继续；不要覆盖 0.3.0 或复用已存在版本。
2. 校验 tarball SHA256 与清单相同，再执行：
   ```sh
   npm publish .git/spec-flow/releases/0.4.0/nightink-spec-flow-core-0.4.0.tgz --access public
   npm view @nightink/spec-flow-core@0.4.0 version dist.integrity --json
   ```
   后一个 integrity 必须与清单一致；registry 安装验证是新的远端事实，尚未完成。
3. 推送已验证的 commit：`git push origin "$RELEASE_SHA:refs/heads/main"`。需要版本标签时再由发布者创建/推送 `v0.4.0`，先核对标签不存在；不需要为 Action 发布一个 npm 包。
4. 调用方按完整已推送 SHA 固定 Action（不要写可变 `main`）：
   ```yaml
   # 先 checkout caller、配置 Node >=22.19.0、安装 caller 的真实测试依赖
   - uses: nightink/pi-spec-flow@<RELEASE_SHA_FULL_40_HEX>
     with:
       purpose: strict   # 修复提交明确选 change；不覆盖 caller 内嵌 strict
   ```
   caller 保持最小 `permissions: contents: read`，自己推送并查看真实 CI；本工具未改 caller、未声称远端已接通。
5. Pi Git 安装/更新由宿主 owner 完成；重新加载后对比 native `engine` 与 CLI `identity`。磁盘更新或这里的离线 SDK smoke 不证明用户常驻进程已加载新版本。
